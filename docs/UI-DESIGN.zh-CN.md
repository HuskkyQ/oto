# TeslaMate Viewer — UI 设计

原生 iOS 17 应用，SwiftUI，中文优先，仅深色。本文档是 SwiftUI 实现的设计依据。
视觉参考：[`mockups/index.html`](mockups/index.html)。English version: [`UI-DESIGN.md`](UI-DESIGN.md)。

---

## 1. 设计意图

应用按顺序回答三个问题：

1. **车现在怎么样？** —— 实时：电量、续航、状态、位置、安全。
2. **车最近去了哪、充了多少？** —— 行程与充电：可读的日志，不是数据倾倒。
3. **长期趋势如何？** —— 统计与历史轨迹：里程、能耗、费用、轨迹。

原则：

- **数据优先，外壳其次。** 文字背后不放装饰性渐变，标题不做超大尺寸把电量数字挤出首屏。
  电量环和续航是唯一的「主角」。
- **只用一种强调色。** 青色只用于导航、选中态和主指标。绿/橙/红/紫只用来表达状态
  （在线、充电中、警告、暂停）。
- **没事发生时要安静。** 停好、锁车、休眠的车看起来应该很静：中性卡片、一个绿色的「在线/休眠」
  药丸，没有动画。
- **绝不在新鲜度上撒谎。** 每个实时页面都显示数据到达时间；过期数据要标注，不能藏起来。
- **拇指优先。** 主要操作放在下半屏或导航栏；所有点击目标 ≥ 44 pt。

每个页面都是单列滚动；只有行程/充电列表按分组列出并使用吸顶日期头。不做横向轮播：
它会藏起数据，也会打乱 VoiceOver 的阅读顺序。

### 2.1 液态玻璃

每个表面都是玻璃，没有一块是纯色面板：

- **背景先行。** 每个页面是一层深色渐变，顶部有很淡的白色光泽，下方三个低饱和色场——
  青色在中左、紫色在右侧、青色系（teal）在底部。玻璃需要东西去着色和模糊；
  在纯色背景上它看起来就是灰塑料。
- **让色彩远离外框带。** 顶部约 120 pt（状态栏 + 顶部栏）保持中性藏蓝。状态栏后面放饱和色场
  会和玻璃打架，看起来像一条硬色带；色彩属于内容区，玻璃会从那里取色。
- **每个表面三层：** 半透明主体（白色 10% → 3% → 5.5%，150° 对角，左上有光泽）、
  1 pt 镜面描边（渐变边框，受光角 50% → 暗角 3%）、一条内顶高光。不做斜面，不堆长阴影。
- **模糊与饱和度一起用：** 相当于 `.ultraThinMaterial` = 模糊 24 pt + 饱和度 175%。
  饱和度是让磨砂玻璃不发灰的关键。
- **圆角随材质变厚：** 卡片 24，瓦片与控件 22，分段滑块 13，按钮 18。玻璃比染色矩形看起来更厚，
  所以圆角要保持足够大。
- **着色承载含义，不做装饰：** 绿色表示能耗，橙色表示警告，红色只用于破坏性操作；
  这些颜色通过主体和描边的渐变进入，绝不用一块纯色填充。
- **外框悬浮。** tab bar 是玻璃胶囊，左右内缩 12 pt、底部内缩 10 pt；顶部栏承载标题与操作，静止时无边框，
  页面滚动后包进同样的玻璃胶囊里（见 2.2）；分段控件是玻璃轨道加玻璃滑块。内容从它们下面滚过。
- **可读性优先于效果。** 正文仍然要落在深色底上 ≥ 3% 白，包裹后的顶部栏内标题与说明落在 ≥ 5% 白；
  在不支持背景模糊的地方，顶部栏改为不透明，而不是让滚动内容在标题后面透出来。
  如果某个表面会让次要文字掉到 4.5:1 以下，提高主体不透明度，而不是把文字调亮。

### 2.2 顶部栏与包裹态

顶部只承载身份与操作；其余一切都属于内容。

- **一条栏，标题加操作。** 每个页面都以同一条栏开场：左侧返回箭头与标题，右侧尾随操作
  （刷新、地图、分享）。没有状态带、没有分隔线、没有背景条。
- **静止时没有外框。** 页面在顶部时，这条栏无边框、通栏到屏幕两边：没有玻璃、没有描边、
  没有圆角。标题直接落在页面上，与 16 pt 内容留白对齐，读起来是页面的第一行，
  而不是一个悬浮的元件。
- **它一直吸附。** 整个滚动过程中顶部栏都停在滚动视图顶端，不再随内容一起上移。
- **一滚动就包裹。** 页面一动（约 8 pt），同一条栏收拢成玻璃胶囊：左右内缩 12 pt、圆角 28、
  内边距 10/16、玻璃主体 + 镜面描边 + 投影，紧贴状态栏下方。包裹过程是 220 ms 的
  `cubic-bezier(.32, .72, 0, 1)` 过渡（作用在内缩、内边距与圆角上），玻璃用 180 ms 淡入；
  滚回顶部时原路展开。栏内元素不单独移动 —— 一条栏，两个状态。
- **筛选器永不放进顶部栏。** 7/30/90 控件（以及统计页的日/月）是顶部栏正下方的一行内容，
  随页面一起滚走。顶部栏在每个页面保持同一高度；再加一条玻璃栏正是让标题看起来像叠层的原因。
- **操作是栏内的纯图标**（白 74%，36 pt 点击区域，无背景、无边框、无阴影）。
  玻璃胶囊里再放一个玻璃圆片会被读成第二种材质，正是它让标题看起来被分段了。
- **不滚动的页面不包裹** —— 充电页没有任何内容会从它后面经过，顶部栏保持无边框。
  **历史轨迹是例外**：它以地图为主，顶部栏落在地图之上，所以从一开始就是包裹态；
  无边框的标题压在地图配色上无法阅读。
- **行程的日期头是另一个吸顶层级**：它们吸附在滚动视图顶部，从包裹后的顶部栏下方经过，
  永不在其之上。
- **历史轨迹以地图为主**：顶部栏与筛选行浮在地图之上，地图本身不滚动，底部抽屉只在内容超出
  高度时内部滚动。
- 不支持背景模糊时，包裹态的顶部栏回退为不透明的 `#18222F` 主体，描边保持不变，
  标题后面不会有内容透出来；静止态不需要回退。
- 包裹后的主体保持在 5% 白以上，这样其中 12 pt 的说明文字对藏蓝底色仍有 4.5:1；
  提升可读性的手段是提高主体不透明度，而不是把文字调亮。

## 4. 页面

### 4.1 引导（仅首次启动）

全屏渐变，无 tab bar。

```
            ◇ (car glyph, accent)
        连接你的 TeslaMate
   使用公网 HTTPS 地址和 Token 安全连接。

  ┌ 服务器地址  https://api.example.com ┐
  ┌ API Token   ••••••••••••••••••••••••  ┐
  [        测试并保存        ]
  填写已部署的公网 HTTPS 代理地址；手机无需 Tailscale。
```

- 代理尚在规划中，尚未部署；`api.example.com` 仅为示例地址。
- URL 键盘，关闭自动大写与自动更正；Token 字段用 `SecureField`，带显示/隐藏切换。
- 「测试并保存」校验 scheme + host，把 Token 写入 Keychain，调用 `GET /v1/cars`，
  然后显示「连接成功 · 1 辆车」再进入 App。
- 失败文案：地址无效 / 401「Token 无效」/ 超时「无法连接服务器，检查网络和服务器地址」。

### 4.2 实时 — Live

顺序：状态 → 电量 → 位置 → 行驶/安全 → 空调 → 车辆 → 导航。

```
★Roadster Lite™                    ⟳
● 在线            最后更新 12 秒前

┌───────────────┐  续航
│    ◯ 74%      │  382 km
│     电量      │  估算 419 km · 额定 382 km
└───────────────┘  充电枪 未连接

┌─────────────── 地图 200 pt ───────────────┐
│        ● 车辆位置                         │
│  杭州市 · 拱墅区                  查看 ↗  │
└───────────────────────────────────────────┘

┌ 速度 ┐ ┌ 功率 ┐
│ 0    │ │ 0.0  │
└──────┘ └──────┘
┌ 里程 ┐ ┌ 挡位 ┐
└──────┘ └──────┘

┌ 车锁 已锁 · 哨兵 关闭 · 车窗 已关 · 车门 已关 ┐
┌ 车内 25.0°C   车外 17.5°C   空调 关闭        ┐
┌ 软件 2026.26.200.11 · Model 3 LR AWD        ┐
```

规则：

- `scenePhase == .active` 时每 3 s 轮询；进入后台停止；下拉刷新始终可用。
- 若 `charging_state == "Charging"`，在电量与地图之间插入 **充电中** 卡片：功率、已充电量、
  当前 SoC → 上限、充满时间。地图下移。
- 若 `active_route.destination != nil`，追加导航卡片；忽略
  `{"error":"No active route available"}`。
- `stale == true` 且状态非休眠 → 橙色横幅「数据已过期，展示最后已知状态」。
  状态为休眠 → 中性文案「车辆休眠 · 数据停在 11月1日 21:01」。
- 电量环颜色随电量变化；闪电仅充电时显示。
- 安全行把四个布尔值压成一行「图标 + 标签」；任一为「开」时变橙，整行可点击展开详情。

### 4.3 行程 — Drives

```
行程                              近 30 天 ▾
[ 7 天 ] [ 30 天 ] [ 90 天 ]

┌ 118.5 km      12 次行程      6 小时 42 分 ┐

11月1日 周六                        4.1 km
┌ 06:02  ● 祥符 · 拱墅区                  ┐
│        │                                │
│ 06:13  ○ 和美弄                 4.0 km  │
│                          11 分钟 · 消耗 4.4 km
└─────────────────────────────────────────┘
...
```

- 汇总条由已加载的当前页在客户端计算（里程、次数、时长）。
- 列表行：开始时间、带绿色起点与橙色终点的竖线、起终点标题（地理围栏名优先于地址）、
  右侧里程 + 时长。
- 日期头：`M月d日 周x` + 当天里程，吸顶。
- 分页：`limit=100`，滚动到 80% 时加载下一页；底部转圈；结束态「没有更多行程」。
- 导航栏 **轨迹** 按钮（地图图标 + 文字）打开历史轨迹，并带上当前时间段。
- 点击 → 行程详情。区间为空 → `EmptyState`，带「切换时间段」操作。

```
  16.3 kWh/100km（能耗徽章，绿色 <18，橙色 ≥18）

┌ 速度 ───────────────────────────── 最高 66 km/h ┐
│        ╱╲      ╱╲╲╱╲                            │
```

- 行程不存在 → 错误横幅 + 返回，绝不空白页。

### 4.5 充电 — Charging

```

[ 7 天 ] [ 30 天 ] [ 90 天 ]

┌ 72.2 kWh 已充      3 次     费用未记录 ┐

  35% ▓▓▓▓▓▓░░░░░░ 81%        33.9 kWh
```

- SoC 变化用一条小横条表示，而不是只给两个数字。
- `cost == null` 的行显示「费用未记录」，绝不显示 ¥0.00。

  （`conn_charge_cable`）、车外温度、有则显示费用。

- 时间段与粒度位于顶部栏正下方的同一行，不放进顶部栏；修改任一项都重新请求，但不重置滚动位置。
- 图表：每日里程、充电电量、行程时长 —— 各一张卡片，共享同一 x 轴。
- 缺失日期补零；按月粒度使用月份标签。
- 数值严格等于 `stats` 接口的汇总；区间内没有任何会话有费用时，费用卡片显示「—」。
- 点击柱子是 **v1.1**（筛选后的行程列表）；不要做到一半就上线。

### 4.7 历史轨迹 — History

**入口。** 历史轨迹不是 tab；五个 tab 始终是 实时 / 行程 / 充电 / 统计 / 设置。

1. **行程 → 导航栏「轨迹」**（地图图标 + 文字）—— 主要入口，拇指可达；带上当前的 7/30/90 天时间段。
2. **统计 → 底部「历史轨迹地图」卡片** —— 用户已经在看聚合数据时的发现型入口。

两个入口推入同一个页面；返回键回到来源 tab。时间段选择器只作用于历史轨迹页，
所以在这里切换不会改变行程/统计页的筛选。

```
‹ 历史轨迹                    [ 7 天 ] [ 30 天 ] [ 90 天 ]

┌──────────────────────────────────────────────┐
│            full-bleed map                    │
│        ╭──────╮  polyline in accent          │
│        ╰──╮   ╰────╮                         │
└──────────────────────────────────────────────┘
 118 km 轨迹 · 1,000 个采样点 · 10月3日–11月2日
 起点 ● 终点 ○           [ 标准 / 卫星 ]
```

- **以地图为主：** 地图占满时间段选择器以下的全部空间，左右出血并延伸到 Home 指示条下方。
  汇总卡片与坐标说明作为底部抽屉浮在地图之上，带柔和渐变遮罩；抽屉下面不再放任何东西，
  所以没有空带。
- 30 天用 `max_points=2000`，90 天用 `5000`。
- 汇总里程是对显示点做 haversine 计算，标注「约」，以免让人以为等同 TeslaMate 里程表精度。
- 区间为空 → 隐藏地图，`EmptyState`「该时间段没有位置记录」。
- 全屏地图支持捏合/旋转；退出后回到抽屉汇总态。

## 5. 状态、动效、无障碍

| 状态 | 处理 |
|---|---|
| 首次加载 | 与最终布局一致的骨架卡片；不用全屏转圈 |
| 刷新 | 下拉刷新 + 导航栏小转圈；已有数据保留 |
| 实时数据过期 | 橙色横幅 + 「最后更新 X」；绝不空白 |
| 网络错误 | `ErrorBanner` 带重试；缓存内容保留并标注 |
| 401 | 横幅 + 「去设置」操作；不静默重试 |
| 列表为空 | `EmptyState`，带一个操作 |
| 加载更多 | 底部转圈；禁止重复请求 |

动效：电量环与图表过渡用 200–300 ms ease-out；首次加载之后不再有微光；
图表不随每 3 s 的轮询重新播放动画（仅当时间范围变化时动画）；遵循 `accessibilityReduceMotion`。

无障碍：

- 电量环标签：「电量 74%，续航 382 公里」；状态药丸播报「车辆状态：在线」。
- 图表提供无障碍摘要（「速度，最高 66 公里每小时」），并在可行处通过 `AXChartDescriptor`
  提供逐点数值。
- 对比度：卡片内主文字 ≥ 7:1；次要文字 ≥ 4.5:1。
- 所有文字支持动态字体；大数字上限 34 pt，但随 `@ScaledMetric` 缩放。
- 每个纯图标按钮都有标签；点击目标 ≥ 44×44 pt。

## 7. 地图与坐标

### 出现位置

| 界面 | 高度 | 内容 | 相机 |
|---|---|---|---|
| 实时 | 约 200 pt 卡片，位于电量下方 | 最后已知位置，一个标记 | 最后位置；跟随新位置，直到用户拖动，之后出现回中按钮 |
| 行程详情 | 约 260 pt 卡片 | 该次行程的折线与起终点 | 按折线自适应，永不自动移动 |
| 历史轨迹 | 顶部栏下方整屏 | 所选区间的轨迹 | 按轨迹自适应，永不自动移动 |
| 统计 | 无 | 打开历史轨迹的卡片 | —— |

四个界面，一种地图样式。App 内其它页面不实例化地图。

### 坐标

- TeslaMate 存储 **WGS-84**；中国大陆的 Apple 地图渲染 **GCJ-02**。
- 仅当 `mapOffsetCorrection` 开启**且**点位于中国境内时才在显示前转换；境外不转换。存储与接口
  中的原始坐标始终为 WGS-84。
- 转换发生在渲染阶段，因此切换开关只重绘，不重新请求。
- 上线前用一个已知坐标验证是否落在正确道路上；若转换有误，会表现为**同一方向**上一致的约
  500 m 偏移，而不是零散漂移。

### 相机

- 四周留白 ≥ 12% 自适应内容；俯仰 0；不旋转；不做 3D 建筑。
- 实时页仅在用户未拖动时跟随车辆。首次拖动即停止跟随并显示回中按钮；点击后恢复视角并继续跟随。
- 行程详情与历史轨迹是静态的：在看一条已经结束的行程时让地图自己动，是干扰不是功能。

### 线与标记

- 轨迹只用一条线：3 pt、圆角连接、强调色——不用渐变、不用发光。
- 起点为实心圆点，终点为箭头；两者靠**形状**区分，因此在灰度与色盲条件下依然成立。
- v1 不做：充电桩标记、地理围栏叠加、聚合、热力图、点击选点。

### 状态

| 状态 | 地图表现 |
|---|---|
| 区间内无位置 | 什么都不画——整个地图框替换为一条提示加一个动作 |
| 接口 400 | 在上一张地图上方显示横幅；最后一次成功的轨迹保留 |
| 离线 | 在空白切片上绘制缓存轨迹，并标注「缓存于 …」 |
| 切换坐标偏移开关 | 同一条轨迹重绘；不显示转圈，不发请求 |

### 无障碍与隐私

- App 从不请求定位，也不绘制用户点；Info.plist 中不存在任何 `NSLocation*` 键。
- 每张地图都有文字替代——「行程轨迹，12.4 公里，从 A 到 B」——地图上显示的每个事实，在地图
  之外都有文字呈现。
- 地图样式：标准、无起伏、无路况。

## 8. v1 UI 不包含

- 车辆指令、推送、小组件、实时活动。
- Android/iPad 专用布局、横屏。
- 离线地图切片；仅离线缓存 JSON（每个页面最后一次成功响应）。
